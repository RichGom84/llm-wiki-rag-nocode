## 수업 준비

- 공개 배포 가능 자료만 저장소에 올립니다. 포함된 원문은 모두 가상 자료입니다.
- 참가자마다 Google 계정과 사용 가능한 API 계정을 준비하게 합니다. API 키는 채팅이나 GitHub에 수집하지 않습니다.
- 현재 모델 기본값은 `gpt-4.1-mini`입니다. 수업 전에 해당 계정의 접근 권한·한도·비용을 확인합니다. 모델을 바꾸려면 `src/workshop.py`의 MODEL을 수정하고 노트북을 다시 생성합니다. 이는 강사용 유지보수 작업입니다.
- CPU 런타임을 사용합니다. 수강생에게 GPU나 유료 Colab 가입을 필수로 요구하지 않습니다. 무료 런타임의 가용성은 보장되지 않습니다.
- 2시간에는 기본 구축·출처 비교·강사 변경 시연, 3시간에는 개인별 갱신·다운로드·GitHub 결과 보관까지 진행합니다.

## GitHub에 배포

저장소가 정해지면 이 프로젝트의 모든 파일을 Git에 커밋합니다. 수강생이 코드 수정 없이 시작하게 하려면 README의 Colab 링크를 설정하세요. 저장소가 비공개이면 ZIP 또는 노트북 다운로드 후 Colab 업로드 경로를 기본으로 안내하세요.

브라우저만 사용할 때는 저장소의 **Add file → Upload files**에서 프로젝트 폴더 안 파일을 올리고 **Commit changes**를 누릅니다. ZIP 파일 하나만 올리면 GitHub에서 원문과 안내서를 읽기 어려우므로 파일을 풀어 올리는 편이 좋습니다.

개발환경을 사용할 수 있는 강사용 명령:

```bash
python tools/configure_repo.py OWNER/REPOSITORY --ref main
python tools/build_notebook.py
python -m unittest discover -s tests -v
git add .
git commit -m "Add no-code RAG and LLM Wiki workshop"
```

위 명령은 강사용입니다. 수강생에게 입력시키지 않습니다. 원문·프롬프트·코드를 고쳤다면 노트북을 재생성해 같은 커밋에 넣습니다. 링크의 브랜치 또는 태그가 실제 존재하는지 확인합니다.

## 수업 전 리허설

1. 새 Colab 세션에서 노트북을 열고 3개 셀을 차례로 실행합니다.
2. API 키 입력이 화면과 저장 파일에 남지 않는지 확인합니다.
3. RAG를 만들고 질문 1, 3, 5, 10을 실행합니다.
4. Wiki 생성 후 목차와 네 페이지, 출처와 링크를 확인합니다.
5. D11을 추가하고 질문 전 갱신 안내를 확인합니다.
6. 갱신 후 일정이 11월 11일·13일로 바뀌고 수료 조건은 그대로인지 확인합니다.
7. ZIP을 받아 실제 파일과 질문 기록을 엽니다.
8. 참가자용 권한으로 GitHub와 Colab 접근을 확인합니다.

## 검증과 비용의 한계

로컬 자동 검사는 모의 AI 응답으로 수행했습니다. 실제 모델 결과와 Colab 브라우저 실행은 별도 리허설 대상입니다. 앱의 토큰 통계는 성공 응답에서 받은 사용량만 합산합니다. 실패·타임아웃 요청의 비용은 공급자 대시보드에서 확인하세요. 최초 Wiki 생성은 4회, 일정 변경 시에는 영향을 받는 일정 페이지만 1회 생성합니다. 질문마다 각 방식이 1회 답변 API를 호출합니다. 자료 수가 늘면 호출량과 입력 크기도 달라집니다.

화면의 응답 시간은 주로 답변 생성 구간입니다. 정확한 전체 성능 벤치마크가 아닙니다. 이번 RAG는 기본 BM25 검색이며 벡터·하이브리드 RAG와 일반적인 성능 우열을 주장하지 않습니다.
