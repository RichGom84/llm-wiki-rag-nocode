# 수강생 안내서

## 오늘 할 일

같은 자료로 RAG와 Wiki를 만들고, 같은 질문을 던지고, 일정 변경을 반영합니다. 프로그램을 설치하거나 코드를 바꾸지 않습니다.

## 화면이 열리기까지

README의 시작 안내를 따라 `START_HERE.ipynb`를 Colab에서 엽니다. 실행 버튼 3개를 위에서부터 누릅니다. 2단계에서는 비밀번호 입력란에 API 키를 넣습니다. 1단계를 다시 실행하면 실습 상태가 새로 시작되므로 결과부터 다운로드하세요.

## RAG 활동

1. 원문 목록에서 D04를 읽습니다.
2. 연습 질문 1번을 선택합니다.
3. `RAG 만들기 / 갱신`을 누릅니다.
4. `검색 근거만 보기`를 누르고 D04가 들어 있는지 봅니다. 이 단계는 AI API를 호출하지 않습니다.
5. `RAG에 질문하기`를 누르고 답과 출처를 비교합니다.
6. 근거 수를 1과 3으로 바꾸고 5번 질문을 비교합니다.

검색 점수는 정답 확률이 아닙니다. 근거 수를 늘린다고 정확성이 항상 높아지는 것도 아닙니다.

## Wiki 활동

1. `Wiki 만들기 / 갱신`을 누릅니다. 최초 생성에는 주제별로 AI 호출 4회가 필요합니다.
2. 페이지 목록에서 `courses.md`를 고르고 `Wiki 페이지 읽기`를 누릅니다.
3. D01·D02·D03의 정보가 종합되었는지 확인합니다.
4. `index.md`와 `schedule.md`도 읽습니다.
5. 같은 5번 질문을 `Wiki에 질문하기`로 실행합니다.

Wiki 페이지가 길어 보여도 원문 조건을 빠뜨릴 수 있습니다. 출처와 대조해 주세요.

## 변경 실험

1. 먼저 7번 질문에 답하게 하고 결과를 기록합니다.
2. `변경 공지 D11 추가`를 누릅니다.
3. 바로 질문하면 갱신이 필요하다는 안내가 나옵니다.
4. `RAG 만들기 / 갱신`과 `Wiki 만들기 / 갱신`을 각각 누릅니다.
5. `schedule.md`를 선택하고 `수정 전후 보기`를 누릅니다.
6. 7~9번 질문을 다시 실행합니다. 일정은 바뀌고 총 시간은 유지되어야 합니다.

## 제출

`결과 ZIP 다운로드`를 누릅니다. ZIP에는 원문·Wiki·변경 이력·질문 기록이 들어 있습니다. 노트북 출력 대신 이 ZIP과 비교 기록을 제출합니다. 런타임 종료 전에 컴퓨터에 파일이 저장됐는지 확인합니다.

## 결과를 본인 GitHub에 보관하기

선택 활동입니다. 본인 저장소에서 **Add file → Upload files**를 선택하고, 다운로드 ZIP을 압축 해제한 `wiki` 폴더의 파일들을 업로드합니다. **Commit changes**를 눌러 변경 이유를 기록합니다. API 키나 계정 정보는 올리지 않습니다. 폴더 구조는 `raw/`와 `wiki/`의 상대 경로를 유지하세요. GitHub 파일 개수 제한에 걸리면 폴더별로 나눠 업로드합니다.

## 알아둘 점

노트북은 강사가 미리 만든 코드를 실행합니다. 수강생이 코딩할 필요는 없지만 AI 호출에는 API 계정과 비용이 필요합니다. RAG는 키워드 기반이며 Wiki도 페이지 검색을 사용합니다. 두 방식 모두 답변은 원문과 대조해야 합니다.
